# US-054: Skill Tree — spending skill points

**Status**: Signed  
**Source**: James — column costs, Fantasy Level row gates, ultimate prereqs  
**Priority**: P1  
**Roles**: Dungeon Master

## User Story

As the Dungeon Master, I spend **skill points** on Skill Tree nodes (DM and Dad tabs) so unlocks follow clear column costs and Fantasy Level progression gates — instead of free ownership.

## Context

US-034 / US-035 own Skill Tree **UI** (tabs, labels, tooltips, owned chrome). US-036–US-053 own each **passive’s gameplay effect** when a node is owned. Those passives’ Open default was “owned with no currency.” **This story supersedes that** for how ownership is earned: spend + gates.

Ultimates (**TSB**, **Dad All Powerful**) are purchase-gated here; their *effects* stay out of scope (TSB TBD; Dad All Powerful **US-021**).

Fantasy Level (`DmManager.fantasy_level`) already exists as a progression integer used for Row 2 / Row 3 gates. Reality Level may still exist for other systems; it does **not** gate Skill Tree spends in this story and does **not** grant SP.

Today node clicks still emit `SignalBus.unlock_skill` without an SP check (US-034 UI-only). This story replaces that with a host `try_purchase` path. Canonical node **ids** are the Skill Tree passives index ([SKILL_TREE_PASSIVES.md](SKILL_TREE_PASSIVES.md)) plus ultimates `tsb` and `dad_all_powerful`. Gameplay MUST align `gui/dm/skill_tree.gd` ids to that catalog if they diverge (e.g. Dad T-Shirt id).

## Locked rules (James)

| Rule | Value |
|---|---|
| Column 1 passive cost | **1** skill point |
| Column 2 passive cost | **2** skill points |
| Column 3 passive cost | **3** skill points |
| Row 2 purchasable when | **Fantasy Level ≥ 10%** (see Open defaults for % → number) |
| Row 3 purchasable when | **Fantasy Level ≥ 50%** (see Open defaults) |
| Ultimate purchasable when | **≥1 owned unlock in each of rows 1, 2, and 3** on **that tree** |

Columns = left→right within a row (col1 / col2 / col3). Rows = themes (DM: Lightning / Gremlins / Goblins; Dad: Frost / Fire / Control).

## Independent Test

Start with SP = 0, FL = 0. Row 1 col1 is available but purchase fails without SP. Raise FL to 10 to earn 1 SP (or grant SP). Buy a Row 1 col1 node for 1 SP; node becomes owned; SP decreases. Attempt Row 2 before FL ≥ 10: rejected with feedback. Raise FL to ≥ 10; buy Row 2 with enough SP. Attempt Row 3 before FL ≥ 50: rejected. Raise FL to ≥ 50; buy Row 3 with enough SP. With ≥1 owned in each row on that tree and ≥5 SP, buy the ultimate; without a row covered, ultimate rejects. Repeat gates on the other tree. Peers see the same owned set and SP. Passive gameplay still only runs when owned (US-036–053). Paper Pusher never spends. Late joiner sees current SP, owned nodes, and correct gate chrome.

## Acceptance Criteria

1. **Given** a new match, **When** the Skill Tree spend system initializes on the host, **Then** SP is **0** and no Skill Tree nodes are owned.
2. **Given** Fantasy Level increases on the host, **When** income resolves, **Then** SP increases by `floor(new_FL / 10) - floor(old_FL / 10)` (**+1 SP per 10 FL**). Reality Level changes MUST NOT grant SP. A jump from 0 to 25 grants **2** SP.
3. **Given** SP is earned or spent on either tree, **When** the DM views the other tree, **Then** the **same** remaining SP is shown (one shared pool).
4. **Given** a column-1 passive on either tree that is not FL-gated and not owned, **When** the DM spends with ≥1 SP, **Then** the host deducts **1** SP and marks the node owned.
5. **Given** a column-2 / column-3 passive (gates OK, not owned), **When** spent successfully, **Then** cost is **2** / **3** SP respectively and the node is owned.
6. **Given** Fantasy Level is 0, **When** the DM views or tries Row 1, **Then** Row 1 is not FL-gated (only SP / already-owned rules apply).
7. **Given** Fantasy Level below **10**, **When** the DM tries to buy any Row 2 node on either tree, **Then** the spend is rejected, SP unchanged, node not owned, and UI shows **row-gate** feedback (not a Reality Level reason).
8. **Given** Fantasy Level ≥ **10** and enough SP, **When** they buy a Row 2 node that is not owned, **Then** the spend succeeds.
9. **Given** Fantasy Level below **50**, **When** they try to buy any Row 3 node, **Then** reject with **row-gate** feedback; SP unchanged. Reality Level MUST NOT be the reason.
10. **Given** Fantasy Level ≥ **50** and enough SP, **When** they buy a Row 3 node that is not owned, **Then** the spend succeeds.
11. **Given** insufficient SP (gates otherwise OK), **When** any purchase is attempted, **Then** reject with **not-enough-SP** feedback; ownership unchanged.
12. **Given** a node already owned, **When** they try to buy it again, **Then** reject with **already-owned** feedback; SP unchanged.
13. **Given** a tree with fewer than one owned passive in any of rows 1–3 of **that** tree, **When** the DM tries to buy that tree’s ultimate, **Then** reject with **ultimate-prereq** feedback. Owned passives on the **other** tree MUST NOT satisfy the prereq.
14. **Given** ≥1 owned in each of rows 1–3 on that tree and ≥5 SP, **When** they buy that tree’s ultimate, **Then** SP deducts **5**, the ultimate is owned (effect body still US-021 / future TSB story).
15. **Given** a successful spend, **When** the host commits, **Then** SP deduct and owned flag are **atomic** (both happen, or neither).
16. **Given** a failed spend, **When** the UI updates, **Then** the DM sees a **distinct** reason among: not enough SP, row gated, ultimate prereq, already owned — and SP/ownership are unchanged.
17. **Given** the same cost/gate matrix, **When** applied to the Dad tree, **Then** results match the DM tree (shared rules, separate ownership and ultimate prereqs).
18. **Given** a client DM, **When** they click a node, **Then** the client **requests** purchase and only the host accepts or rejects; peers (including late join) agree on SP remaining and owned nodes for both trees, and have enough FL to render gates.
19. **Given** a purchased passive id from the catalog, **When** US-036–053 effect code queries ownership, **Then** it reads owned. Harness force-own remains allowed for isolated effect tests.
20. **Given** a Paper Pusher client, **When** they play, **Then** they cannot open this spend UI or change SP/ownership.
21. **Given** no-refunds v1, **When** the DM owns a node, **Then** there is no refund control; if FL later drops, already-owned nodes stay owned and new Row 2/3 buys use current FL.
22. **Given** the Skill Tree panel is open, **When** SP or FL changes, **Then** remaining SP, per-node cost, and gated/unaffordable/available/owned chrome refresh without reopening the panel.
23. **Given** two purchase attempts for the same node in one host frame (double-click), **When** the host serializes them, **Then** at most one success.

## Functional Requirements

- **FR-001**: Host MUST maintain a DM **skill point** integer balance, **starting at 0** each match, and replicate it to the DM client for UI.
- **FR-002**: Passive purchase costs MUST be **1 / 2 / 3** SP for columns **1 / 2 / 3** on both trees, per the **Node catalog**.
- **FR-003**: Row 2 nodes MUST be purchasable only when Fantasy Level ≥ **10** (Open default).
- **FR-004**: Row 3 nodes MUST be purchasable only when Fantasy Level ≥ **50**. Reality Level MUST NOT gate Row 3 (or any Skill Tree spend).
- **FR-005**: Row 1 nodes MUST NOT require an FL gate.
- **FR-006**: A tree’s ultimate MUST require **≥1 owned passive in each of rows 1, 2, and 3** on **that** tree before purchase. The other tree’s ownership MUST NOT count.
- **FR-007**: Ultimate SP cost MUST be **5** (Open default unless James overrides) for both `tsb` and `dad_all_powerful`.
- **FR-008**: Successful spend MUST be atomic on the host: deduct SP and set owned together, or neither.
- **FR-009**: Failed spends MUST NOT change SP or ownership and MUST surface distinct UI feedback with stable reason codes: `not_enough_sp`, `row_gated`, `ultimate_prereq`, `already_owned`.
- **FR-010**: Purchase attempts MUST go through the existing Skill Tree UI (US-034/035). Do not invent a second tree screen. Clicks MUST request host purchase; they MUST NOT grant ownership locally.
- **FR-011**: US-036–053 (and later ultimate effect stories) MUST key off ownership produced by this story. Harness may still force-own for isolated effect tests without spending SP.
- **FR-012**: SP income MUST be **+1 SP per 10 Fantasy Level** on the host (`floor(FL/10)`). Multi-step FL increases MUST grant one SP per ten crossed.
- **FR-013**: SP MUST be **one shared pool** across DM and Dad trees (not per-tree).
- **FR-014**: Reality Level MUST NOT grant SP in v1.
- **FR-015**: Host MUST identify every purchasable node by the **Node catalog** (`tree`, `id`, row, column, cost). Ids MUST match SKILL_TREE_PASSIVES.md / ultimates `tsb` and `dad_all_powerful`.
- **FR-016**: Clients MUST request spends via a host RPC (or equivalent); only the host MAY mutate SP or ownership.
- **FR-017**: v1 MUST NOT implement refunds or respec.
- **FR-018**: Owned nodes and remaining SP MUST persist for the match through DM death/respawn.
- **FR-019**: The Skill Tree UI MUST show remaining SP and each node’s SP cost (1 / 2 / 3 / 5) while the panel is open.
- **FR-020**: Node chrome MUST distinguish **gated** (FL or ultimate prereq), **unaffordable** (gates OK, not enough SP), **available** (can buy now), and **owned**. Reuse US-034 locked / available / owned frames; add cost badge and fail toast from this story’s art.
- **FR-021**: Paper Pushers MUST NOT spend, request spends, or see this spend UI.
- **FR-022**: While the panel is open, SP and FL changes MUST refresh affordability chrome and the SP counter without requiring a close/reopen.
- **FR-023**: The host MUST serialize purchases so a node is owned at most once.
- **FR-024**: Late join MUST receive current SP, owned ids for both trees, and Fantasy Level sufficient to render gates.

## Multiplayer Requirements

- **MR-001**: Only the host accepts spends; clients request and display results.
- **MR-002**: Late join MUST receive current SP, owned nodes (both trees), and enough FL to render gates correctly.
- **MR-003**: Fail reasons MUST be sent to the requesting DM client so feedback is not host-only.

## Edge Cases

- FL drops (if ever possible): already-owned nodes stay owned; new Row 2 / Row 3 buys use current FL.
- Buying ultimate then refunds (unsupported): ultimate stays owned.
- Concurrent double-click buy: one success max (host serializes).
- Dad vs DM trees: SP shared; row prereqs are per-tree for ultimates.
- FL jumps by more than 1 (d20, etc.): grant +1 SP per ten FL crossed (`floor(new/10) - floor(old/10)`).
- Panel open during FL/SP change: chrome and counter update live (FR-022).
- Existing `SignalBus.unlock_skill` / click-to-own path: MUST NOT grant ownership once this story is live.
- Systems note: Director may already have partial spend plumbing — Gameplay should hook UI to host spend API without duplicating economy.
- Id mismatch between `skill_tree.gd` and SKILL_TREE_PASSIVES.md: catalog in this story wins; fix the UI id.

## Key Entities

- **Skill points (SP)**: Spend currency for tree nodes; shared integer on the DM.
- **Owned node**: Host flag consumed by US-036–053 / ultimate effect stories.
- **Row / column gates**: Fantasy Level thresholds and per-tree ultimate prereqs (no Reality Level spend gate).
- **Fail reason**: One of `not_enough_sp`, `row_gated`, `ultimate_prereq`, `already_owned`.

## Assumptions

- Percent gates map to absolute levels vs cap 100 until James defines otherwise.
- Paper Pushers never spend on this tree.
- Ultimate **effects** remain out of scope; owning the node is still required so later stories can key off the flag.
