# US-033: Mini-map for all players

**Status**: Signed  
**Source**: James — mini-map; shared PP fog; separate DM map  
**Priority**: P2  
**Roles**: Paper Pusher, Dungeon Master

## User Story

As a Paper Pusher or Dungeon Master, I use a mini-map of the play area so I can see bounds, buildings, Reality / Fantasy zones, and players — with Paper Pushers **sharing** explored map info as a team, while the DM keeps a **separate** map that does not feed the PP team (and vice versa).

## Context

There is no mini-map today. PP and DM each have role HUDs (`gui/player/player_hud.tscn`, `gui/dm/dm_hud.tscn`) plus the shared top bar (`gui/hud.tscn`). Map geometry lives in `MapBounds` / `LevelManager` (cliff interior, dungeon AABB, US-024). Zone claim is US-001 / US-003 / US-025 (`ZoneDriftClaim`, home ∪ pockets). Buildings are host-placed under `building_root`. Players are peers under `PlayerManager` / `DmManager`.

This story adds a **cell-grid mini-map** for every player. It does not change occupancy, claim, or combat — only HUD knowledge.

## Open defaults (James signed)

These filled gaps James did not pin at write time. **Signed at `219629e` — defaults below are the contract unless he overrides.**

| Topic | Default for v1 | Why |
|---|---|---|
| What reveals for PP | **Visit radius**, not raycast LOS. Each living PP permanently reveals cells within **Chebyshev radius 3** of their current cell onto the **shared PP reveal set**. Explored stays revealed (classic fog, not forgetting). | Cheap, readable, team-friendly; LOS occlusion is a later polish. |
| DM reveal | Same visit-radius rule, but into a **private DM reveal set**. PP reveals never merge into DM’s set and DM reveals never merge into PP’s. | Matches James’s isolate default. |
| Ally markers (PP) | **All living Paper Pushers always shown** on the PP mini-map (not fog-gated). | Team coordination in a co-op office. |
| Enemy markers (PP) | **DM marker only while the DM’s cell is currently revealed** on the shared PP map (in the reveal set). No sticky last-known ping in v1. Monsters / summons **off** the mini-map in v1. | Asymmetric info; keep v1 readable. |
| Markers (DM) | DM **self always** shown. **Each living PP** shown only while that PP’s cell is in the **DM reveal set**. Monsters off in v1. | Same fog rule both ways. |
| Dungeon on map | **Full cliff-interior grid** including dungeon cells. Cells start fogged until revealed by the role that can walk them (DM explores dungeon; PPs usually cannot enter — US-015 — so PP maps stay fogged there unless a later rule lets them in). No special “hide dungeon mass” silhouetting in v1 beyond fog. | One grid, one code path; exit forest / overworld still readable. |
| UI chrome | **Bottom-right** corner panel on both PP and DM HUDs. **Visible by default**. Toggle with **`M`**. v1 is **fit-to-interior** (whole play area in the widget); no free pan/zoom in v1 (scroll-wheel zoom is out of scope). | Standard RTS/ARPG mini-map muscle memory; avoids fighting build/spell targeting. |
| Authority | **Host** owns both reveal sets; clients paint from replicated state. Clients must not invent reveals. | Matches inventory / zone host patterns. |
| Late join | Host sends a **full snapshot** of the shared PP reveal (to PP joiners) or the DM reveal (to a DM joiner) before/with first mini-map paint. | No empty fog until they walk. |

Call-outs for James: radius `3`, always-on ally pips, no monster icons, no sticky enemy pings, `M` toggle, fit-only (no zoom), dungeon cells fogged until visited.

## Independent Test

Two Paper Pushers and one DM in a match. PP A walks a path: PP B’s mini-map gains the same revealed cells without B walking them. DM walking elsewhere does **not** clear PP fog and does not appear on the PP map until a PP’s visit radius covers the DM. DM mini-map does not show PP-explored cells the DM never approached. Both roles see map bounds, revealed buildings, and Reality / Fantasy washes on revealed cells. Toggle `M` hides/shows the widget. A late-joining PP receives the current shared PP reveal.

## Acceptance Criteria

1. **Given** a Paper Pusher or DM in a live match, **When** their HUD is up, **Then** a mini-map widget is present (bottom-right by default) showing the cliff-interior play area.
2. **Given** the mini-map is visible, **When** the owner presses `M`, **Then** it hides; press `M` again and it shows. Other HUD controls still work.
3. **Given** PP A reveals cells via visit radius, **When** PP B views their mini-map, **Then** those cells are revealed for B (shared PP set) without B visiting them.
4. **Given** the DM reveals cells on the DM map, **When** any PP views the PP mini-map, **Then** those DM-only cells stay fogged on the PP map (sets stay isolated).
5. **Given** PP-only reveals, **When** the DM views the DM mini-map, **Then** those cells stay fogged on the DM map until the DM’s own visit radius covers them.
6. **Given** revealed cells, **When** the mini-map paints, **Then** it shows Reality-claimed and Fantasy-claimed washes (home ∪ pockets, US-025 rules) and building markers for buildings whose cells are revealed.
7. **Given** the PP mini-map, **When** two PPs are alive, **Then** both PP markers are visible regardless of fog; the DM marker appears only if the DM’s cell is in the shared PP reveal set.
8. **Given** the DM mini-map, **When** PPs are alive, **Then** the DM marker is always visible; each PP marker appears only if that PP’s cell is in the DM reveal set.
9. **Given** unrevealed cells, **When** painted, **Then** they read as fog (no building icons, no zone wash, no enemy markers).
10. **Given** a PP late-joins after shared reveals exist, **When** their mini-map first paints, **Then** it matches the host’s shared PP reveal set (not empty).
11. **Given** a DM late-joins after DM reveals exist, **When** their mini-map first paints, **Then** it matches the host’s DM reveal set.

## Functional Requirements

- **FR-001**: Every player (each Paper Pusher **and** the DM) MUST have a mini-map UI on their role HUD. Default placement: **bottom-right**. Default visibility: **on**. Toggle action: **`M`** (must not steal build/spell confirm).
- **FR-002**: The mini-map MUST cover the **map interior** inside the cliff ring (US-024). Cell size follows `DungeonGrid` / `MapBounds`. v1 MUST fit the full interior in the widget (no pan/zoom required).
- **FR-003**: Fog of war MUST use two host-owned reveal sets: **`pp_shared_reveal`** and **`dm_reveal`**. They MUST NOT merge.
- **FR-004**: While a Paper Pusher is alive, the host MUST add every cell within **Chebyshev distance ≤ 3** of that PP’s cell to `pp_shared_reveal` (tunable constant). Reveals are **sticky** for the match (no decay in v1).
- **FR-005**: While the DM is alive (and, if still in dungeon, while they move on dungeon or overworld cells), the host MUST add cells within the same radius to `dm_reveal` only.
- **FR-006**: On revealed cells the mini-map MUST paint: terrain/bounds context, **Reality** vs **Fantasy** claim wash (pocket override / exclusive homes per US-025), and **building** markers (unique or typed icons — Art supplies chrome; Gameplay may use colored rects until art lands).
- **FR-007**: Player markers MUST follow the Open defaults table (PP allies always on PP map; cross-role markers only on that side’s revealed cells; no monster markers in v1).
- **FR-008**: Reveal updates and snapshots MUST be **host-authoritative**. Clients MUST NOT expand reveal sets locally beyond prediction that is corrected by the host (preferred: no client-side invent; paint only replicated bits).
- **FR-009**: On late join, the host MUST send the full reveal set appropriate to the joiner’s role before or with first paint (AC10 / AC11).
- **FR-010**: The mini-map MUST NOT change world occupancy, claim, damage, or vision in the 3D/2D play space — HUD only. Missing art MUST NOT block a colored-rect prototype.

## Multiplayer Requirements

- **MR-001**: All PP clients MUST converge on the same `pp_shared_reveal` contents.
- **MR-002**: DM clients MUST receive only `dm_reveal` (PP clients must not need DM reveal payloads).
- **MR-003**: Marker positions for other peers MUST use host-known transforms / cell indices, not unverified client guesses.

## Edge Cases

- PP dies: stop expanding reveal from that body; existing shared reveals remain; dead PP marker hidden or ghosted (default: **hidden** until respawn).
- DM dies / respawns: same for `dm_reveal`; marker follows respawn cell and resumes radius.
- Building destroyed / rebuilt: marker updates on next paint; revealed cell stays revealed.
- Zone home pushback / pocket spawn (US-025 / US-031): washes update from live claim on revealed cells without re-fogging.
- Very large interior: fit-to-bounds may make cells tiny — acceptable for v1; do not add zoom in this story.
- Input: `M` while typing in a future chat UI — out of scope; today there is no chat focus steal.

## Key Entities

- **Mini-map widget**: Corner HUD control on PP and DM HUDs.
- **`pp_shared_reveal`**: Host bitset / cell set shared by all Paper Pushers.
- **`dm_reveal`**: Host bitset / cell set private to the DM.
- **Visit radius**: Chebyshev r=3 reveal brush around a living mover.

## Assumptions

- One DM and N Paper Pushers per match.
- “Relevant others” means ally PPs + opposing role when fog allows — not creeps.
- Signed defaults above stand unless James overrides them.

## Out of Scope

- Raycast / occlusion LOS.
- Sticky last-known enemy pings.
- Monster / projectile / pickup icons on the mini-map.
- Free pan, scroll-wheel zoom, click-to-move, or ping-on-map.
- Changing actual world fog or hiding entities in the play view.
- Skill Tree / inventory layout reflow beyond making room for the corner widget.
