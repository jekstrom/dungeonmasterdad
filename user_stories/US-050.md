# US-050: Skill Tree passive — Everything Burns

**Status**: Draft  
**Source**: James — gameplay for Dad tree passive from US-035  
**Priority**: P2  
**Roles**: Dungeon Master

## User Story

As the Dungeon Master, when I **own** the Skill Tree passive **Everything Burns**, fireball destroys world resource pickups so the node’s tooltip matches live play.


## Context

US-018 fireball; world pickups wood/iron/paper/forms; US-035 UI. UI copy lives on the Dad tab (US-035). This story owns the **gameplay effect** only.

## Open defaults (confirm with James)

| Topic | Default for v1 | Why |
|---|---|---|
| Scope | **Gameplay** — implement the passive effect when the matching Skill Tree node is **owned** on the host. | Director: not UI-only. |
| Unlock / spend | **No currency spend in this story.** Effect applies when the host marks the node **owned** (wire to US-034/035 owned chrome when ready). Harness/debug may force-own. A future economy story may gate ownership. | No spend system yet. |

## Independent Test

Force-own **Everything Burns** on the host (debug or harness). Verify: Fireball now destroys resources. Observe a control case with the node **not** owned where the bonus does not apply. Peers see the same combat/world outcome. Unequip/clear ownership (if supported) or start a fresh match without ownership and confirm baseline returns.

## Acceptance Criteria

1. **Given** **Everything Burns** is **not** owned, **When** the related system runs, **Then** baseline behavior from the referenced stories applies (no this-passive bonus).
2. **Given** **Everything Burns** is **owned** on the host, **When** the related system runs, **Then** Fireball now destroys resources.
3. **Given** ownership flips mid-match (if supported), **When** the next relevant action runs, **Then** the effect matches current ownership without requiring a full reconnect.
4. **Given** multiple peers, **When** the effect changes the world or combat, **Then** all peers observe the same authoritative outcome.
5. **Given** only UI interaction without ownership, **When** the player views the US-035 node, **Then** labels/tooltips still match US-035 and no effect applies until owned.

## Functional Requirements

- **FR-001**: Host MUST track ownership of skill id `everything_burns` (or equivalent) for this passive.
- **FR-002**: While owned, the host MUST apply: Fireball now destroys resources. Suggested: fireball impact destroys (removes) world resource pickups in radius; does not wipe player inventory by default.
- **FR-003**: While not owned, the host MUST NOT apply this passive’s bonus.
- **FR-004**: This story MUST NOT implement Skill Tree currency spend, row unlock gates, or ultimates.
- **FR-005**: UI labels/tooltips remain US-035; do not regress the Dad tab copy.
- **FR-006**: Effect application MUST be host-authoritative; clients MUST NOT grant the bonus unilaterally.

## Multiplayer Requirements

- **MR-001**: Ownership and effect outcomes MUST agree across peers.
- **MR-002**: Late joiners MUST receive current ownership (or re-derive from host snapshot) before relying on the bonus.

## Edge Cases

- Own then DM death/respawn: ownership persists for the match unless a later rule clears trees on death (default: **persists**).
- Related unlock missing (e.g. knightling locked): owning this passive does not by itself unlock the base ability; it only modifies behavior when that system runs.
- Stacking with other passives: combine unless a conflict is documented in a later balance pass.

## Key Entities

- **Skill ownership**: Host flag for `everything_burns`.
- **Everything Burns**: Passive effect described above.

## Assumptions

- Tooltip numbers may be flavor until tunables are locked in playtest.
- Base systems named in Context exist enough to hook (stubs OK with harness force).

## Out of Scope

- Ultimates (TSB; Dad All Powerful / US-021).
- Redesigning US-035 panel chrome.
- Full skill-tree spend economy.
- Other passives (each has its own US).
