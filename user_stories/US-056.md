# US-056: Monster A* pathfinding (around walls)

**Status**: Signed  
**Source**: James — A* so monsters path around walls and other obstacles; must stay performant  
**Priority**: P1  
**Roles**: Dungeon Master, Paper Pusher

## User Story

As a Paper Pusher or Dungeon Master, when a monster chases me (or a factory, pile, or flee goal), it **walks around walls, cliffs, and solid obstacles** instead of sliding into them or giving up on the far side of a hallway.

## Context

Monster chase today is a straight line. `EnemyStateAggro._chase_character` sets `velocity = direction_to(target) * run_speed`. Goblin raid approach, skeleton/knightling aggro, and Baja Blast boss chase do the same. Gremlins (US-013) clamp/steer onto walkable ground but still do **not** search a route around a wall.

Dungeon generation already has a **BFS** on walkable cells (`PathValidator`) for **layout connectivity**, not runtime AI. `MapBounds.is_world_position_walkable` is the **cliff/interior** clamp, not dungeon walls. Those stay as they are.

This story owns a **shared host pathfinder** that AI states **follow**. It does **not** change aggro, raid damage, lethal rolls, gremlin pickup rules, or spawn placement (US-011 / US-012 / US-013 / US-055).

World tiles stay `DungeonGrid.CELL_PX` = **128**. Runtime A\* uses a **32px** path grid (4×4 path cells per tile) so 40px wall segments do not leave a 64px invincible halo. Host-only: `EnemyStateMachine` already runs on the server.

## Locked rules (James)

| Rule | Value |
|---|---|
| Algorithm | **A\*** on the **128px cell grid** |
| Obstacles | Path **around** walls and other solid blockers; never through them |
| Performance | MUST stay cheap with many monsters; no per-physics-frame flood fill per unit |

## Open defaults (confirm with James)

| Topic | Default for v1 | Why |
|---|---|---|
| Connectivity | **4-connected** (N/E/S/W). No diagonal corner-cut through walls. | Matches dungeon hallways and `PathValidator` / `DungeonGrid.neighbors`. |
| Engine primitive | Occupancy on a **32px** path grid; routes via host **`AStarGrid2D`**. Live walls from collision segments, not full 128px tiles. Rebuild when occupancy dirties, not per unit. | 40px wall colliders cannot be represented on 64px cells without a player-only halo. |
| Who uses it | All host-driven **monsters**: goblin, gremlin, knightling, skeleton, Baja Blast boss **chase** (not the jet projectile). Any catalog spawn that uses `EnemyStateAggro` / wander. | One service; no per-species graph. |
| Walkable cells | Union of: dungeon `walkable_cells` **and** floor/entrance/exit tiles (the exit **door** is a floor not in `walkable_cells`), plus overworld **interior** (not cliffs / void), minus **wall tiles** and **solid occupancy**. Cells that neighbor dungeon floors but are not the door (or door-adjacent overworld) are **sealed** so the only way out is the exit. `blocked_cells` leftover is **not** occupancy. | Same notion as “can stand here.” Gremlins inside the dungeon must leave through the exit door, not through a south-wall hole. |
| Solid occupancy | Floors stamp on the **south-foot sprite origin** (`-64, -127`). Live walls block from **collision segments** (H/V) on the 32px grid, not the full 128px tile. Layout-wall fallback (tests) stamps the aligned tile. | 32px matches 40px segments; full-tile stamps made players invincible in the halo. |
| Other units | **Not** solid for A\*. Monsters MAY overlap slightly. | Dynamic unit solids thrash the grid every frame. |
| When to repath | Goal **cell** changes, current path is empty/invalid, next waypoint is blocked, or interval **0.4s**. **Never** every physics frame. | Biggest perf win. |
| Line of sight | Steer straight at the goal only if the segment is walkable **with body clearance**, the next step is walkable, and the body is not already sliding on a wall. Otherwise use the path. | Occupancy-only LOS clips wall vertices; physics then sticks. |
| Frame budget | At most **8** A\* searches **per frame**. Extra requests queue. Each search MAY cap expansions (Open default **512** nodes); return a **partial** path toward the goal if capped. | Hard cap so a crowded fight cannot hitch. |
| Path cache | Optional short cache keyed by `(start_cell, goal_cell)` (Open default TTL **0.25s**). Invalidated when occupancy dirties. | Repeat chases share work. |
| Follow | If the goal is in walkable LOS, go straight there. Otherwise the path is a polyline: drop the cell you are in and reached vertices, skip ahead while the next vertex is visible, steer at the next remaining vertex. Never stop on an intermediate cell center. | Intermediate cell centers are not destinations. |
| No path | Do **not** walk through the wall. Stop, keep last walkable steer, or fall back to wander — never clip occupancy. | Fail closed. |
| Occupancy dirty | Rebuild/update the grid when dungeon commits, map interior commits, a building places/destroys, or a wall-equivalent doodad changes. Incremental region update preferred over full rebuild on large maps. | Keep A\* correct after US-011 rubble / US-001 buildings. |
| Gremlin inland (US-013) | Keep inland **preference** as a **small extra A\* cost** on cliff-adjacent cells, not a second pathfinder. | FR-012 stays; one graph. |
| Wander | Wander MUST NOT walk into walls. If the chosen cardinal is blocked, pick another walkable dir or A\* to a nearby wander cell. | Today wander is a random cardinal. |
| Baja jet | **Out of scope** (projectile). Boss **walk-chase** uses this service. | |
| Client | Clients do **not** run A\*. They show host movement (existing replication). | Matches enemy SM. |

## Independent Test

Stand a Paper Pusher (or the DM) on the far side of a dungeon wall / L-hallway from a goblin, knightling, or skeleton. The monster walks the hallway around the wall and reaches melee — it does not pin on the wall face. Place a factory around a corner: the goblin paths around to raid range. Spawn a gremlin with a wood pile behind a wall: it goes around, still inland-biased vs cliffs. Spawn a gremlin **inside the dungeon** with a pile in the overworld: it leaves through the exit door (it does not stay trapped in the dungeon AABB). Block the only corridor: the monster stops instead of walking through the wall. Spawn a pack (10+) and chase: the game stays playable; path work is staggered (not one hitch when all aggro at once).

## Acceptance Criteria

1. **Given** a living monster and a chase/raid/flee/pickup goal on the other side of a wall, **When** it moves on the host, **Then** it follows a walkable A\* route around the wall and does not slide along or through the wall tile.
2. **Given** an L-shaped or winding hallway of walkable cells, **When** a monster chases a target at the other end, **Then** it traverses the hallway (not the blocked interior).
3. **Given** a goblin raiding a factory whose origin is not in line of sight, **When** it approaches, **Then** it uses the same pathfinder to a stand-off cell adjacent to the building, then existing raid strike/retreat (US-011) takes over at melee range.
4. **Given** a gremlin pathing to a pile, while carrying, fleeing, or wandering (US-013), **When** a wall or cliff is in the way, **Then** it uses this pathfinder (inland cost still applies) and never leaves walkable cells.
5. **Given** knightling, skeleton, and Baja Blast boss **chase**, **When** they pursue a valid aggro target, **Then** they use this pathfinder (boss jet unchanged).
6. **Given** wander with no aggro, **When** a random step would enter a wall/cliff/void, **Then** the monster does not take that step.
7. **Given** line of walkable cells from the monster’s cell to the goal cell, **When** a path is requested, **Then** A\* is skipped and the monster walks that line.
8. **Given** no walkable path to the goal, **When** a path is requested, **Then** the monster does not enter blocked cells; it stops or wanders on walkable ground.
9. **Given** occupancy changes (dungeon commit, building placed/destroyed, interior/cliffs), **When** the next path is requested, **Then** the grid reflects the new solids (old paths that hit a new wall are discarded).
10. **Given** many monsters requesting paths in one frame, **When** the host simulates, **Then** at most the signed search budget runs that frame; the rest queue. The host MUST NOT hitch from unbounded A\*.
11. **Given** a monster already has a valid path whose goal cell is unchanged, **When** physics ticks before the repath interval, **Then** it follows waypoints and does not recompute A\*.
12. **Given** a client peer, **When** a monster paths, **Then** they see the host locomotion; they MUST NOT run a second A\* that diverges.
13. **Given** two monsters and one corridor, **When** both path, **Then** both may use the corridor (units are not A\* solids). They still collide with walls.
14. **Given** generation `PathValidator`, **When** this story ships, **Then** layout connectivity tests still use BFS at generate time; runtime AI MUST NOT call that BFS every tick.

## Functional Requirements

- **FR-001**: Host MUST own a single shared cell occupancy + A\* service used by monster AI (not one graph per monster).
- **FR-002**: Search MUST be A\* (or `AStarGrid2D` A\*) on `DungeonGrid` cells, **4-connected**, with walls/cliffs/void/solid occupancy blocked.
- **FR-003**: Path results MUST contain only walkable cells. Follow MUST move toward waypoint centers without entering blocked cells.
- **FR-004**: `EnemyStateAggro` character chase MUST follow this service instead of raw `direction_to(target)`.
- **FR-005**: Goblin building approach MUST path to a legal stand-off cell; strike/retreat timing stays US-011.
- **FR-006**: Gremlin move-to-pile / flee / wander MUST use this service; US-013 inland bias MUST remain as extra cell cost near cliffs.
- **FR-007**: Wander and Baja Blast boss chase MUST use walkable pathing (jet excluded).
- **FR-008**: The service MUST skip A\* when a walkable 4-connected line to the goal exists.
- **FR-009**: The service MUST cap **searches per frame** (Open default 8) and MAY cap expansions per search (Open default 512), queuing or returning a partial path.
- **FR-010**: Repath MUST be event/interval based (Open default 0.4s or goal-cell change / invalid path), not every `_physics_process`.
- **FR-011**: Occupancy MUST update when dungeon layout, map interior, or solid buildings/doodads change.
- **FR-012**: No-path MUST NOT produce a route through solids.
- **FR-013**: Clients MUST NOT compute this A\*.
- **FR-014**: `PathValidator` remains generation-only.

## Multiplayer Requirements

- **MR-001**: Only the host computes paths and sets monster velocity/position.
- **MR-002**: Peers (including late join) see monsters at replicated positions; they MUST NOT need the occupancy grid to look correct.
- **MR-003**: Path internals MUST NOT be replicated (no path array RPC). Locomotion replication is enough.

## Edge Cases

- Goal on a blocked cell (inside a wall / building interior): path to the nearest walkable cell adjacent to the goal (stand-off), then existing melee/raid range checks apply.
- Goal cell moves every frame (running player): repath on **cell** change and interval, not pixel change.
- Monster already in melee range: do not A\*; existing melee/raid code wins.
- Partial path from expansion cap: follow it, then repath.
- Occupancy dirty mid-follow: drop path and requeue.
- Monster spawned in a wall (should not happen post US-055): snap/steer to nearest walkable, then path.
- Stun / trap / death: clear path; do not search while not locomoting.
- Blizzard slow (US-017 / US-031): speed changes only; path still valid.
- Reality vs Fantasy: walkability is collision/occupancy, not zone type (skeletons still despawn in Reality per US-001).
- Huge overworld interior: prefer dirty-rect updates; do not rebuild the entire `AStarGrid2D` from scratch on every tree harvest.

## Key Entities

- **Occupancy grid**: Per-cell walkable vs blocked, shared on the host.
- **Path request**: Start cell, goal cell, optional flags (inland bias).
- **Waypoint path**: Sequence of walkable cells the monster follows until repath.
- **Search budget**: Max A\* runs (and optional expansions) this frame.

## Assumptions

- 128px cells are coarse enough that waypoint following looks acceptable without steering around every sprite.
- Peak live monsters are tens, not hundreds; the frame budget is the safety net if that grows.
- Building footprints can be mapped to cells the same way occupancy already thinks about placement (US-001 / US-007).
- James wants **A\*** specifically; flow fields / JPS are allowed later if profiling says so, but v1 is A\* on the shared grid.

## Out of Scope

- Paper Pusher or DM pathfinding / click-to-move.
- Projectile / jet / fireball steering.
- Crowd pathing, local avoidance, or treating other monsters as A\* solids.
- Changing aggro tables, damage, lethal rolls, gremlin carry rules, or spawn radii.
- Replacing `PathValidator` generation BFS.
- Baking Godot NavigationRegion2D polygons.
- New monster art.

## Required New Art Assets

None.

## Performance (non-negotiable)

v1 is **wrong** if it is correct-but-hitchy.

- **No** A\* in `_physics_process` per monster.
- **No** GDScript BFS/Dijkstra over the full map per unit per tick (`PathValidator` is not a runtime AI loop).
- **No** navmesh rebake when a monster moves.
- Shared native grid + LOS skip + repath interval + per-frame search cap are the default recipe.
- Headless harness SHOULD assert a search-count cap (AC10) so a 20-monster aggro spike cannot run 20 full searches on one frame.
