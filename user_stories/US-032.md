# US-032: Generated dungeon exit forest

**Status**: Draft  
**Source**: James — forest immediately outside procedural dungeon exit  
**Priority**: P2  
**Roles**: Dungeon Master, Paper Pusher

## User Story

As a player leaving or approaching the procedural dungeon exit, I always find a **dense forest** (tree doodads + the Skill Tree) immediately outside that exit so the overworld gate reads as woods, and that forest moves whenever generation moves the exit.

## Context

Dungeon generation places a distinct exit (US-015; `EntranceExitResolver`, exit room / exit door via `tile_placement_builder`, `level/dungeon_exit.tscn`). Map layout puts the dungeon on the **east** interior edge; the exit faces the overworld (west toward Paper Pushers) so the DM lands on **outside** tiles (US-023 / US-024).

US-024 already scatters sparse `TreeDoodad`s (`doodads/tree.tscn`) across interior outside cells and **blocks** the exit cell and its neighbors so the gate stays clear. That sparse scatter is **not** a forest at the exit. The Skill Tree (`doodads/skill_tree.tscn`, `SkillTreeDoodad`) is currently **hand-placed** in `playground.tscn` and does not follow generation.

This story owns a **dense exit forest** on outside cells immediately beyond the live exit. It uses existing tree and Skill Tree doodads. Harvest rules stay US-006. Sparse map fill stays US-024 (this story carves the exit pocket so the two placements do not fight). DM exit landing and re-entry stay US-015.

## Independent Test

Generate a dungeon, note the exit door / overworld landing. Immediately outside that exit (not inside dungeon cells) there is a visibly dense cluster of trees and one Skill Tree. Walk the egress: at least one clear outside cell lets the DM leave without spawning inside a trunk. Regenerate or move the exit: the old forest is gone and a new forest (trees + Skill Tree) sits beyond the new exit. No tree or Skill Tree sits on a dungeon footprint cell. Sparse US-024 trees elsewhere still exist and still avoid the exit pocket.

## Acceptance Criteria

1. **Given** a successful dungeon generation with a known exit, **When** the overworld is built, **Then** a dense forest of `TreeDoodad` instances exists on **outside** cells immediately beyond/outside that exit.
2. **Given** that forest, **When** every tree (and the Skill Tree) cell is checked, **Then** none lie inside the dungeon AABB / dungeon footprint, and none sit on cliffs or outside the map interior (US-024).
3. **Given** the Skill Tree, **When** the forest is placed, **Then** exactly **one** `SkillTreeDoodad` exists in the match forest, inside the exit forest pocket (not dungeon, not west PP spawn strip).
4. **Given** the DM uses the exit (US-015), **When** they step onto overworld outside tiles, **Then** at least one clear egress cell at the landing is free of tree / Skill Tree collision so exit is usable.
5. **Given** a new generation where the exit cell / door moves, **When** forest rebuild runs, **Then** forest trees and the Skill Tree are cleared and re-placed for the **new** exit; no orphan forest remains at the old exit.
6. **Given** US-024 sparse tree scatter, **When** both systems run, **Then** sparse scatter does **not** place trees inside the exit forest pocket (no double trunks); sparse trees elsewhere still follow US-024 density.
7. **Given** another peer, **When** the host has placed the exit forest, **Then** all peers see the same tree cells and Skill Tree position (host-authoritative / shared seed from exit + bounds).

## Functional Requirements

- **FR-001**: After dungeon + map commit, the host MUST place a **dense** forest of existing `TreeDoodad` instances on eligible **outside** cells immediately beyond the procedural dungeon exit (door / overworld landing side). Suggested default: high fill of the pocket (well above US-024’s ~4–12% sparse density), tunable.
- **FR-002**: Forest eligibility MUST exclude: dungeon footprint cells, cliff cells, non-interior cells, the Paper Pusher west spawn strip (US-024), and building-blocked cells if any exist at place time. Trees MUST NOT overlap the dungeon.
- **FR-003**: The forest pocket MUST be derived from the **live** exit (exit door / `dungeon_exit_cell` / overworld landing). When generation moves the exit, forest placement MUST follow it (rebuild or equivalent).
- **FR-004**: Exactly one `SkillTreeDoodad` MUST be placed in that forest pocket per match (reuse `doodads/skill_tree.tscn`). Authored playground Skill Tree MUST NOT remain the match source once this placement runs (remove, hide, or replace on match start).
- **FR-005**: Placement MUST leave a clear **egress** for US-015: the exit door cell and at least one adjacent outside landing cell MUST remain free of forest trees and the Skill Tree.
- **FR-006**: Forest trees MUST be normal harvestable `TreeDoodad`s (US-006) unless a later story says otherwise. This story does not change harvest hits, wood yield, or stump rules.
- **FR-007**: US-024 sparse scatter MUST treat the exit forest pocket as blocked (same idea as today’s exit-neighbor block, expanded to the pocket) so sparse and dense systems do not double-place.
- **FR-008**: Placement MUST be host-authoritative and deterministic from committed interior + dungeon bounds + exit (shared seed / replicate positions). Late joiners MUST see the same forest.
- **FR-009**: This story MUST NOT change dungeon generation topology, exit combat (US-017 boss in exit room), or Skill Tree HUD unlock contents — only **where** the Skill Tree doodad sits in the world.

## Multiplayer Requirements

- **MR-001**: Host decides forest cells and Skill Tree cell; peers MUST match.
- **MR-002**: Rebuild on map/dungeon apply MUST not leave divergent forests across peers.

## Edge Cases

- Exit flush to east edge with thin west pad: pocket clips to interior outside only; still dense enough to read as woods if any eligible cells exist.
- Zero eligible outside cells (degenerate bounds): do not place trees inside the dungeon; surface/log failure rather than punching dungeon cells.
- Skill Tree cell contested with egress clear: prefer Skill Tree off the primary landing cell; never block the mandatory clear egress.
- Regenerating mid-match (if supported): clear previous forest group before re-place.
- Mines (US-007): prefer not stacking a mine on forest Skill Tree / dense pocket if another cell is free (mine scatter already avoids trees when possible).

## Key Entities

- **Dungeon exit**: Generated exit door / overworld landing (US-015).
- **Exit forest pocket**: Outside cells immediately beyond that exit.
- **TreeDoodad**: Dense forest filler; harvestable (US-006).
- **SkillTreeDoodad**: Single interactable skill hub in the forest.

## Assumptions

- “Immediately beyond/outside” means the overworld side of the exit (west of an east-flush dungeon), not cells inside the exit room.
- Dense means a local pocket, not turning the whole overworld into forest.
- One Skill Tree per match is enough; skill HUD behavior stays as today.

## Out of Scope

- Sparse overworld tree density elsewhere (US-024 T012).
- Wood harvest combat numbers (US-006).
- Skill unlock graph / HUD contents (existing DM skill UI).
- Changing dungeon exit art or portal rules (US-015).
- Baja Blast boss spawn in the exit room (US-017).

## Required New Art Assets

None required. Reuse `doodads/tree.tscn` (`sprites/tree.png`) and `doodads/skill_tree.tscn` (`sprites/skill_tree_*_128.png`).
