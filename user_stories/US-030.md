# US-030: Inventory — active vs static rows

**Status**: Draft  
**Source**: James — inventory rows, hotkeys, drag-swap  
**Priority**: P2  
**Roles**: Paper Pusher, Dungeon Master

## User Story

As a player (Paper Pusher or Dungeon Master), I keep **usable items** on a hotkeyed top row and **ingredients** on a bottom row, rearrange them by dragging, and hold a slot key to finish a channel so that inventory is one bag UI for everyone.

## Context

PP HUD and DM HUD both instance `player/inventory/inventory_ui.tscn`: a **4-column** `GridContainer` with `PlayerManager.max_inv_slots = 8` (two rows of four). That grid is not two bag types yet.

- Host inventory is a **dict** `{ item_path: quantity }` on `PlayerManager.players_data` — **no slot index**, no row, no owner-controlled order. The HUD rebuilds from `SignalBus.inventory_updated` in dict order.
- Clicking a slot calls local `ItemData.use()` and decrements quantity **without the host**.
- The same scene is the only inventory widget. Building **one** slotted UI and **one** host slot list (keyed by peer id, including the DM) covers both roles. `ItemData.pickup_char` already decides who can pick an item up.

This story makes the 4×2 grid **active (top)** vs **static (bottom)**, binds **Q E R T** to the four active cells, paints distinct cell colors, and allows **drag-swap** within a row. Use and layout are host-authoritative. Role-specific effects (form fill, dice, Dew) stay in their stories; this story only **which cell** is used.

## Independent Test

As a PP or as the DM, pick up one **active** item and one **static** item that character is allowed to carry. They land in the **top** and **bottom** rows. Top cells show **Q E R T**. Tap/hold the occupied active hotkey: the host runs that cell’s use. Hold a channel item for the full duration to complete; release early cancels. Drag two items in the same row: they swap. Drag static onto active (or the reverse): rejected. Cell background colors differ by row.

## Acceptance Criteria

1. **Given** the local player’s inventory HUD (PP or DM), **When** it is shown, **Then** there are two rows of four: **top = active**, **bottom = static**, with **distinct background colors**.
2. **Given** the four active cells left-to-right, **When** they render, **Then** they display **Q**, **E**, **R**, **T** in the **upper-left** of each cell.
3. **Given** an active cell that holds an item, **When** the owner presses that cell’s hotkey, **Then** the host activates **that cell** (not a globally bound item type).
4. **Given** the item’s use is a **channel**, **When** the owner uses the hotkey, **Then** they must **hold** it until the channel finishes; **releasing** cancels with no complete. Move, damage, and death still cancel.
5. **Given** an instant use, **When** the owner taps the hotkey, **Then** the host resolves one use.
6. **Given** an empty active cell, **When** its hotkey is pressed, **Then** nothing is used.
7. **Given** a click-drag onto another cell, **When** the drop is legal, **Then** the cells **swap** (empty target = move).
8. **Given** a static item dropped on an active cell, or an active item on a static cell, **When** the drop resolves, **Then** both stacks stay put.
9. **Given** a new unique stack is granted, **When** the host places it, **Then** it takes the first empty cell of **its** row. If that row is full, it **drops** even if the other row has space.
10. **Given** another peer, **When** the owner rearranges or uses a slot, **Then** only that owner’s HUD must match the host.

## Functional Requirements

- **FR-001**: Every player who has this HUD (each Paper Pusher **and** the DM) MUST have the same slotted bag: **4 active + 4 static**. `max_inv_slots` stays 8. Same `resource_path` still stacks **in one cell**.
- **FR-002**: `ItemData` MUST declare **active** or **static**. The host MUST reject the wrong row. `pickup_char` still gates pickup; it does not replace the row flag.
- **FR-003**: Default active hotkeys left-to-right MUST be **Q**, **E**, **R**, **T**. Draw the **currently bound** key in the **upper-left** of that cell.
- **FR-004**: A hotkey MUST use the item **in that cell**. Dragging from Q to R means **R** uses it.
- **FR-005**: If `ItemData` marks the use as a channel, the hotkey MUST be **held** for the full duration. Release cancels. Instant uses fire on press. Channel length and success effects stay with the item’s existing story (e.g. US-009 fill).
- **FR-006**: Use, grant, and swap MUST be host-validated. Do not keep client-only `ItemData.use()` + local qty decrement as authority.
- **FR-007**: Click-drag MUST move/swap **within the same row**. Wrong row → no change.
- **FR-008**: Active and static cells MUST use **distinct background colors**.
- **FR-009**: World **interact** MUST NOT stay on **E** (both PP and DM currently bind `interact` to E). Rebind interact (suggested **F**). Inventory QERT MUST be the same InputMap for every local player.
- **FR-010**: Host slot state MUST be per **peer id** (PP peers and the DM peer) and pushed to **that** owner’s HUD. One inventory widget; do not fork a DM-only bag UI.

## Suggested row flags (defaults)

Set on `ItemData`; implementers may adjust if a later story needs it.

| Row | Examples |
|---|---|
| Active | Paper (create form), blank form, tax form, filled form, Dew, dice, cloak, Code Red, Baja (usable / effect items) |
| Static | Wood, metal, coal, stone (ingredients / costs) |

What a use **does** is unchanged: PP form fill/file and DM pickup effects keep their own stories. This story only routes **use the selected active cell**.

## Multiplayer Requirements

- **MR-001**: Only the owning peer’s hotkeys and drags MAY change that peer’s slots. The host MUST reject anyone else’s swap/use.
- **MR-002**: After use or swap, the owner’s HUD MUST match the host.
- **MR-003**: Late join: the owner MUST get their **slotted** bag, not a reshuffled dict.

## Edge Cases

- Drag onto self: no-op. Drag off the grid: snap back (no world drop in this story).
- Same `resource_path` dropped on a same-row stack: swap is enough; merge is optional.
- Hotkey while dead, placing a building, or otherwise locked: no use.
- Inventory controls MUST be `FOCUS_NONE` so QERT is not eaten by buttons.
- Full active row and a new active item: **drop**; do not spill into static.
- Existing global keys that collide with QERT (**R**/**T** fill, **E** interact, US-009 **F** create-form) MUST be moved or removed so they do not double-fire with slot use.

## Key Entities

- **Active row**: Four usable cells, Q E R T, top.
- **Static row**: Four ingredient cells, no use hotkey, bottom.
- **Slot**: Peer + row + index + item path + quantity. Host truth.
- **Channel use**: Hold-to-complete, release-to-cancel.

## Assumptions

- 4 + 4 is v1. No third row.
- Hotkeys bind to **cells**, not item types.
- One `inventory_ui` for PP and DM. No separate DM layout.
- Channel duration and outcomes are owned by the item, not this HUD story.

## Out of Scope

- Office Max (US-010), gremlins (US-013).
- Drag-off-HUD to drop in the world.
- A full keybinding options screen.
- Changing `max_inv_slots` away from 8.
- Factory / IRS / spell-bar buttons (except moving `interact` off E).

## Required New Art Assets

None. Cell colors and hotkey `Label`s are enough.
