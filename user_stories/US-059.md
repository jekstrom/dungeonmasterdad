# US-059: DM wizard sprite sheets (walk, melee, cast)

**Status**: Draft  
**Source**: James — DM should look like a wizard: red robe, brown hat, Dew can on the hip; walk and melee with a staff; cast with a d20  
**Priority**: P1  
**Roles**: Dungeon Master

## User Story

As the Dungeon Master, I see **myself as a wizard** — **red robe**, **brown wizard hat**, **green Mountain Dew can on my hip** like a potion — with **up / down / side** animations for **walking**, **melee attacking** (wooden staff), and **casting a spell** (d20) so I read as Dad-the-dungeon-master, not a recycled Paper Pusher sword sprite.

## Context

Today `dm/dm.tscn` draws `dm/sprites/PlayerSprite02.png` (`hframes = 16`, `vframes = 3`). Clips already exist: `idle_{down,side,up}`, `walk_{down,side,up}`, `attack_{down,side,up}`. Left is `sprite.scale.x = -1` on the **side** row (`dm.gd` `apply_aim` / `anim_direction`). There is **no** cast clip: spell targeting (`SignalBus.start_spell_cast` → reticle) leaves the body on idle/walk.

This story **replaces the body art and wires the clips**. Combat, mana, unlocks, and spell VFX stay on their own stories (US-014, US-018 fireball, US-031 blizzard, melee hurtbox).

Sheet contract is `/create-sprite-animation`: **128×128** cells, **3 facings** (down, side, up), **4 frames** each, **12 cells per state**, side faces **right**.

## Independent Test

Host as DM. Standing: idle wizard (red robe, brown hat, Dew on hip, staff). Walk each facing: 4-frame walk, left is a flipped side. Melee: staff swing on `attack_*`, hurtbox still pulses. Open a spell reticle (fireball or blizzard): body plays `cast_*` with the d20, still the same wizard, Dew still on the hip. Cancel or confirm the spell: body returns to idle/walk. A joining client sees the same sheets and clips, not `PlayerSprite02`.

## Acceptance Criteria

1. **Given** the DM is in the world, **When** any peer looks at him, **Then** they see the wizard identity (red robe, brown hat, green Dew can on the hip) — not `PlayerSprite02.png` as the live texture.
2. **Given** the DM is standing, **When** idle plays, **Then** `idle_down` / `idle_side` / `idle_up` use the idle sheet, 4 frames per facing, staff in hand.
3. **Given** the DM walks, **When** each cardinal is held, **Then** `walk_down` / `walk_side` / `walk_up` loop 4 frames; left uses the side row flipped.
4. **Given** the DM melee-attacks, **When** the attack state runs, **Then** `attack_*` plays a 4-frame **staff** swing on the attack sheet; existing hurtbox pulse still happens (damage numbers unchanged).
5. **Given** the DM has a spell reticle up, **When** targeting is live, **Then** `cast_*` plays (d20 in hand) for the current facing; walking/melee do not keep showing the sword/PP body.
6. **Given** targeting ends (confirm or cancel), **When** the DM is standing or walking, **Then** idle or walk clips resume (staff, not d20).
7. **Given** each shipped sheet, **When** inspected, **Then** it is **512×384**, 128×128 cells, rows down/side/up, 4 frames per row, side facing right, consistent scale/palette/foot baseline.
8. **Given** a joining client, **When** the host walks, attacks, and targets a spell, **Then** the client sees the same wizard clips (`AnimationPlayer:current_animation` already replicates).

## Functional Requirements

- **FR-001**: Art MUST ship four RGBA PNGs under `dm/sprites/`: `dm_idle.png`, `dm_walk.png`, `dm_attack.png`, `dm_cast.png`, each 512×384 with 128×128 cells in down/side/up row order.
- **FR-002**: Every cell MUST show the same wizard: red robe, brown pointed hat, green Dew can on the hip. Walk/idle/attack MUST show the wooden staff as the melee/walk prop. Cast MUST show a **d20** as the casting prop.
- **FR-003**: `dm.tscn` MUST play `{idle,walk,attack,cast}_{down,side,up}` from those sheets. `hframes = 4`, `vframes = 3` per texture. Left MUST keep `scale.x = -1` on side frames.
- **FR-004**: `update_animation("walk"|"idle"|"attack")` MUST keep working. Targeting MUST call `update_animation("cast")` (or equivalent) for the live facing and restore idle/walk when targeting clears.
- **FR-005**: Generation MUST follow `/create-sprite-animation` (one canonical down lock, no fresh identity per frame, PIL exact 128 cells).
- **FR-006**: Melee hurtbox timing, damage, mana, spell projectiles, and HUD icons MUST NOT be retuned here.
- **FR-007**: South-foot y-sort MUST still hold (sprite offset / origin unchanged in spirit: feet at the node origin).

## Multiplayer Requirements

- **MR-001**: Body texture and clip names MUST be the same on every peer (scene + replicated `current_animation`).
- **MR-002**: Clients MUST NOT pick a different sheet. No second generate on join.

## Edge Cases

- Aim changes during walk/cast: facing clip updates; texture stays the state’s sheet.
- Attack during targeting: existing code blocks melee while the reticle is up (`wants_melee_attack`); keep that.
- Missing a sheet on disk: fail the story; do not silently fall back to `PlayerSprite02` in production once this ships.
- Hat/staff/Dew clipped by the 128 box: regenerate that cell; do not shrink the character inconsistently.
- Death / respawn overlay: keep current death flow; no new die sheet in v1.
- HUD portrait / skill-tree dad icon: out of scope (may still show old art).

## Key Entities

- **DM wizard body**: Four 128px 3-dir sheets on `dm.tscn`.
- **Staff**: Walk / idle / melee prop.
- **d20**: Cast prop while targeting.
- **Dew can**: Hip potion, all states.

## Assumptions

- One DM body; no class variants.
- Mountain Dew can is the **green** classic can silhouette ( paler green aluminum, not Code Red / Baja).
- Staff is wood, not a pencil or sword.
- d20 is a recognizable twenty-sided die, large enough to read in 128px.

## Out of Scope

- New spells, mana costs, or reticle VFX.
- DM death / respawn sheet.
- HUD / skill-tree portraits.
- Paper Pusher restyle.
- 8-way facings or a left-facing row.
- Changing `generate_on_ready` or dungeon knobs.
